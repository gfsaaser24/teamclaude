Data path — solid lines

Every model request enters TeamClaude on :3456. TeamClaude picks an account, then egresses either straight to Anthropic or into CLIProxyAPI. Those two are exclusive.

The trick

CLIProxyAPI is registered inside TeamClaude as just another account — one whose upstream is a loopback port instead of api.anthropic.com. That is the whole bridge.

Control plane — dashed lines

Orca carries no traffic. It writes config, spawns and supervises the CLIProxyAPI process, registers the bridge account, and syncs the model list. Requests never pass through it.

One inbound shape, three wire formats

You send the same pair every time — thinking:{type:"adaptive"} plus output_config:{effort}. Drop the thinking half and CLIProxyAPI discards the effort silently, which looks exactly like effort doing nothing.

Hot-swap from the status bar

Both halves already have a mechanism — neither is wired to the popup yet

Nothing here needs Claude Code to cooperate, because Orca owns the terminal and TeamClaude owns the wire.

  • Model, in the running session. Orca already exposes a pty:write channel into a live pane, so the popup can type /model <id> straight into the session. The CLI's own header stays truthful because the CLI really did switch.
  • Model, without touching the session at all. TeamClaude already ships rewriteModel(body, modelMap) and rewrites body.model per account on egress. A popup-set override would retarget the next request — though the CLI would keep displaying the old name, which is why the pty route is the honest one for a visible swap.
  • Effort. No session interaction is possible or needed — the CLI has no command for it. TeamClaude is the only place that can inject the thinking/output_config pair into every outgoing request, which is also the only way to set it mid-session rather than at launch.

The gap is a small write path on the TeamClaude side plus the popup UI. The routing underneath already does the hard part.
